## Architecture Notes

- **Colors are programmatic, not CSS.** Selection (blue), hover (blue+thicker), and normal (black) styles are set in code via `stroke`/`fill` properties, not via CSS classes. CSS classes (`segment`, `line`, `ray`, `point`, `circle`) are still added to nodes for test assertions and potential future CSS use, but colors are applied after CSS to ensure they aren't overridden.
- **Hover is canvas-level.** `hoveredId` lives on `CanvasPane`, not on individual tools. The canvas calls `hitTester.hitTest()` on every mouse move and passes the result to the renderer.
- **`LinearLike` is an interface, not a sealed class.** Kotlin exhaustive `when` on `GeometricObject` (sealed) can't resolve `is LinearLike` / `is PointLike` branches as exhaustive. Where needed, `getObjectAnchor()` (in `model/ObjectMetadata.kt`) uses early-return `if` checks for `PointLike`/`LinearLike` followed by a `when` with `else` for the remaining types.
- **`LinearType` enum lives in `geometry/Line.kt`**, not in `IntersectionUtils.kt`. `LinearData` remains in `IntersectionUtils.kt`.
- **Built-in constructions use `startApplyMode()`** with `"Linear"` as the type string for any-LinearLike inputs. `ConstructionApplicator.matchesExpectedType()` resolves `"Linear"` → `obj is LinearLike`.
- **`ReflectionPoint` reflects across the infinite line** defined by a `LinearLike` parent's direction, regardless of whether the parent is a Line, Ray, or Segment.
- **Construction preview uses a dedicated scene graph group.** `constructionPreviewGroup` is a sibling of `previewGroup` in `worldGroup` (not nested inside it), so tool previews (segment/circle ghosts) and construction previews don't interfere. `ConstructionApplicator.computePreview()` creates temporary objects with negative IDs to avoid collision with the real object map. `startApplyMode()` accepts an optional `previewProvider` callback; preview appears only on last-input hover.
- **Selection state is centralized via helpers.** Selection lives in three places: `selectionTool.selectedIds`, `canvasPane.selectedIds`, and `sidebar`. `SketchpadApp` provides `clearSelection()` and `setSelection(ids)` local functions that sync all three. All call sites use these helpers. `requestRender()` also syncs from `selectionTool` → canvas/sidebar (idempotent).
- **AtlantaFX Primer Light theme.** Applied via `Application.setUserAgentStylesheet(PrimerLight().userAgentStylesheet)` at the top of `start()`, before any UI construction. The theme styles all standard JavaFX controls (menus, dialogs, tables, buttons). Programmatic colors and `geometry.css` structural styles are unaffected — scene stylesheets override the user agent stylesheet.
- **Window size and pane ratios.** Window is 1440×720 and dividers are 30%/40%/30% to accommodate the theme's wider cell padding.
- **Label hit-box accounts for scaleY=-1 visual shift.** The renderer uses `text.scaleY = -1.0` to un-mirror labels in the y-flipped world group. JavaFX pivots this around the layout-bounds center, shifting the visual text ~7px below the computed baseline. `LabelTool.hitTestLabel()` extends its hit box downward (`labelY - 10` to `labelY + 18`) to match the actual visual position.
- **`APP_VERSION` is the single source of truth for the version string.** Defined as a top-level `const val` in `Main.kt`. Referenced by `DiagramSerializer`, `ConstructionSerializer`, and the About dialog.
- **Diagram open validates before resetting.** `SketchpadApp` parses and validates the file's version before calling `resetDiagram()`, so a version mismatch doesn't destroy the user's current work. The entire open operation is wrapped in a try-catch that shows an error alert.
- **jpackage uses `org.beryx.runtime` plugin with hardcoded modules.** The plugin's auto-detection (`suggestModules`) crashes on deeply-nested Kotlin anonymous classes. Modules are explicitly set to `java.base`, `java.desktop`, `java.logging`, `jdk.unsupported`. The jpackage `appVersion` is read from `APP_VERSION` in `Main.kt` at build time (macOS jpackage rejects versions starting with `0`). The `.icns` icon at `packaging/macos/EuclideanSketchpad.icns` was generated from `app-icon.png` via `sips` + `iconutil`.
- **Rendering constants and utilities are centralized in `GeometryUtils`.** `POINT_RADIUS`, `STROKE_WIDTH`, `LINE_EXTENT`, `ARROWHEAD_SIZE`, `ANGLE_ARC_RADIUS`, `FONT_SIZE`, and `VIEWPORT_MARGIN_FRACTION` are defined once there and imported by `GeometryRenderer`, `LineTool`, and `ExportRenderer`. Shared functions include `clipLineToRect` (Liang-Barsky), `clipCircleToArcs`, `clampToRect`, `computeClipRect`, `computeArrowheadVertices`, and `computeAdaptiveGridSpacing`. `getObjectAnchor()` is a top-level function in `model/ObjectMetadata.kt`.
- **Viewport clipping uses a 2% margin inset.** `GeometryRenderer.renderAll()` and `renderPreviewObjects()` receive `viewportBounds` from `CanvasPane.getViewportMathBounds()`, compute a clip rect inset by 2% via `GeometryUtils.computeClipRect()`, and clip lines/rays/circles to it. Lines/rays use Liang-Barsky; circles use `clipCircleToArcs` which computes visible arc segments via circle-rectangle intersection. All tools receive a shared `viewportProvider` lambda from `SketchpadApp`.
- **Point clamping is viewport-aware.** Free points created by `PointTool` or auto-constructed via `ToolUtils.resolveOrCreatePoint()` are clamped to the clip rect. `SelectionTool` clamps `FreePoint` drag destinations. Derived points (intersections, semi-free, construction results) are not clamped.
- **Export clipping uses the same 2% inset.** `ExportRenderer` clips lines/rays/circles in math coordinates against a 2% inset of the export bounds, then transforms to pixel coordinates. For auto-fit exports, `computeAutoFitBounds()` uses an 8% margin (4× `VIEWPORT_MARGIN_FRACTION`) for comfortable padding beyond the clip boundary.
- **Angle hit-testing uses zoom-aware arc radius.** Unlike other hit-test tiers that use the snap radius, the angle tier uses `ANGLE_ARC_RADIUS / scale` to match the visual arc size exactly. `Angle.containsPoint()` checks if the point is within the arc sector at this radius. First match wins (no distance tiebreaker), similar to regions.
- **Table visibility is view-only state.** The View menu has Show/Hide toggles for Object List, Custom Constructions, and Measurements. Each table header also has an "X" close button wired to the same toggle. `Sidebar` exposes `setConstructionsVisible()`, `setMeasurementsVisible()`, and `isRightPaneEmpty` for the right pane's internal `SplitPane`. `SketchpadApp.updateMainSplitLayout()` rebuilds the outer `SplitPane` items based on which panes have visible content. Visibility is not persisted or undo-tracked.
- **`javafx.scene.layout.Region` is not imported in `Sidebar.kt`** to avoid shadowing the geometry `Region` class used in the exhaustive `when` in `getTypeName()`. The layout `Region` (used as a spacer in header `HBox`es) is referenced by fully qualified name.
- **Pan-on-all-selected uses callback lambdas.** `SelectionTool` receives `allObjectsSelected` and `panViewport` lambdas from `SketchpadApp`. When all manager objects are in `selectedIds`, dragging calls `panViewport` with screen-pixel deltas (same `appendTranslation(dx/mxx, dy/myy)` math as `CanvasPane`'s Space+drag). No undo checkpoint is created for pan drags, and objects are not deselected on release.
- **Headless export requires JavaFX Application.** PNG export uses `Node.snapshot()`, which needs the JavaFX toolkit. `HeadlessExportApp` is a full `Application` subclass that receives args via a companion object static field (standard pattern since `Application.launch()` doesn't forward constructor args). `main()` in `Main.kt` dispatches to it when `--export` is the first arg; otherwise launches `SketchpadApp` as before — no behavior change for normal app launch.
- **Export label offsets negate `labelOffsetY` and add a baseline shift.** The canvas renderer positions labels at `anchorY + offsetY` in world coordinates and applies `scaleY = -1` to un-mirror text — the visual flip implicitly inverts the offset direction and also shifts the visual baseline by `ascent - descent` pixels (due to JavaFX pivoting the scale around the layout bounds center). The export renderers use `ty()` (which already flips y mathematically), so they apply `ty(anchorY) - offsetY + baselineShift` where `baselineShift = -(layoutBounds.minY + layoutBounds.maxY)` to match the canvas visual position.
